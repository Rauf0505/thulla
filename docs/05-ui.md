# Mobile-first UI / UX

English classic card table: warm ivory page, deep green felt, muted gold detail, serif editorial headings, readable sans-serif controls. Responsive foundation was authored before engine integration.

## Screens

Lobby: guest name, create table, room code join, rules. Waiting room: compact seats, ready state, copy invitation, host bot management and deal. Game: opponents, current trick, active seat, server deadline, resolution feedback, private hand, selected card, explicit Play. Inter-trick: take-hand action. Result: loser and host rematch. Reconnect banner and offline fallback explain connection state.

## Layout requirements

320px minimum; phone portrait is primary. Use safe-area bottom padding, dynamic viewport units for overlays, wrapping opponent layout, and a separately scrolling hand. No page-level horizontal overflow. Cards are at least 72px wide in the interactive hand; every card is reachable. Played cards can be smaller because they are informational. Long names truncate within a bounded seat. There are seven opponent positions at eight seats.

At 768px increase table and lobby breathing room; at 900px introduce the wide editorial layout. At 1280px constrain the page width. Landscape remains usable with vertical page scrolling.

## Accessibility

Select a legal card then confirm Play. Mandatory suit and turn legality are communicated through disabled cards and server feedback. Cards expose full suit names to assistive technology; suit glyphs supplement red/black. Use keyboard-operable native buttons, visible focus outlines, labelled inputs, 44px controls, and reduced-motion CSS. Feedback uses status announcements. Rules are an accessible modal with close control. Manual screen-reader and physical-device checks remain release gates.

PWA installation relies on browser install UI. Cache static chunks and offline assets only; live gameplay requires network. Offline navigation displays a reconnect screen; actions are never queued for later execution.
